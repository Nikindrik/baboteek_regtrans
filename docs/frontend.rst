BI-дашборд
==========

Frontend находится в ``frontend/`` и собирается Vite/React. Nginx публикует
статический bundle на ``:8088`` и проксирует Backend API/WebSocket/Swagger.

Основной экран
--------------

Dashboard предназначен для диспетчера и показывает:

* число активных ТС;
* число ТС с валидным прогнозом;
* ТС в статусе «Мониторинг»;
* ТС без текущей цели в горизонте 10–15 минут;
* среднюю ML latency и количество fallback predictions;
* карту текущих позиций;
* цветовой риск green/yellow/red только при валидном прогнозе;
* активные карточки инцидентов;
* What-if результаты без изменения основного live-прогноза.

Статусы
-------

``Мониторинг``
  Телеметрия поступает, но для рейса нет schedule-backed прогнозного контура.

``Нет цели 10–15 мин``
  Расписание есть, но сейчас отсутствует target в строгом прогнозном окне.

``В графике``
  Есть валидный прогноз и низкий риск.

``Риск`` / ``Критический``
  Валидный ML-прогноз указывает на повышенный/высокий риск задержки.

``Нет связи``
  Backend пометил ТС как offline/stale.

Сетевое взаимодействие
----------------------

Frontend не обращается к ML напрямую. REST и WebSocket проходят через nginx к
Backend, поэтому UI всегда отображает то же состояние, которое используется
для incident/What-if логики.
